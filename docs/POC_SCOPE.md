# Périmètre du PoC Full Stack

Référence prioritaire : blueprint CPU bilingue du 16 novembre 2026, lu intégralement (15 pages). MASAR reste l'application React existante, avec son branding, ses composants, les cinq étapes et les quinze formulaires. Aucun déploiement extérieur.

Les trois espaces principaux sont **Assigned Children** (opérationnel), **Intelligent Browser** et **Recommandation**. Les deux derniers utilisent les mêmes contrôles d'accès, le même retrieval et la même gateway privée.

Sont opérationnels sur des données exclusivement synthétiques : sessions locales de démonstration, affectations datées, rosters, dossier minimisé, observation, formulaires et versions, contribution aux objectifs et roadmap, recherche textuelle, calculs prédéfinis, RAG local et suggestions consultatives. L'avis professionnel n'a aucun effet automatique sur un plan. La planification est une autre commande métier.

Les cinq étapes restent visibles. Les parcours tardifs, transferts institutionnels, clôtures, intégrations nationales et décisions complexes sont conservés dans le code historique mais désactivés pour ce PoC. Les anciennes données d'étapes ultérieures sont historiques, pas une preuve de workflow opérationnel. Le circuit institutionnel de validation des jalons reste à confirmer.

À la demande explicite du 16 novembre 2026, `src/config/features.ts` réactive le réseau professionnel sous le nom **Forum / المنتدى**, accessible depuis le menu principal à l'adresse historique `/network`. Publications générales, commentaires, réactions, favoris personnels et conversations synthétiques sont raccordés à PostgreSQL, avec autorisation serveur, finalités dédiées et RLS forcée. Les conversations restent réservées à leurs membres ; aucune donnée de dossier n'est automatiquement reprise dans les échanges, aucun modèle IA ni envoi externe n'intervient. `ENABLE_PROFESSIONAL_NETWORK` contrôle l'activation de l'API. Les politiques de démonstration restent à valider institutionnellement.

Les fonctions avancées de fin de parcours restent désactivées et leurs routes affichent un statut reporté. La création et l'administration du catalogue restent soumises à un futur circuit de validation ; le catalogue synthétique existant est réutilisé.

L'identité e-Houwiya officielle est **déconnectée**. Les politiques de démonstration sont configurables en base, sans valeur de politique ministérielle. Les modèles locaux testés ne constituent ni une validation professionnelle, ni une homologation de sécurité.

La réponse du SLM est une sélection extractive réellement exécutée sur CPU, limitée à une source fournie et vérifiée. La synthèse générative libre est partiellement implémentée puis restreinte après un ajout non sourcé observé ; elle doit faire l'objet d'une évaluation qualité avant réactivation. Le reranker facultatif est reporté pour respecter le budget mémoire.
